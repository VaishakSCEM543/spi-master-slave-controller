# 04 — SPI Fundamentals

This document explains SPI from absolute basics — starting at the problem level, not the protocol level.

---

## 1. What is a Communication Protocol?

Suppose two people want to exchange information.  
They need to agree on:

- When to speak
- When to listen
- How to signal the start and end of a message
- What the words mean

Without these rules, communication breaks down.

In digital electronics, two devices also need agreed-upon rules for exchanging data.  
These rules are called a **communication protocol**.

**SPI is one such protocol.**

---

## 2. The Problem SPI Solves

Consider a microcontroller (STM32) and a motion sensor (MPU-6500).

The sensor constantly measures acceleration, gyroscope, and temperature.  
The STM32 needs to read that data as fast as possible to control a motor, balance a drone, etc.

```
Physical motion
      │
      ▼
MPU-6500 sensing circuitry
      │
      ▼
Internal sensor registers / FIFO
      │     ← SPI is here
      ▼
STM32 (reads the stored measurement)
      │
      ▼
Application (motor control, drone stabilization, etc.)
```

SPI is the **communication path** between the sensor's internal registers and the MCU.  
It is not the mechanism that measures orientation — it only transfers the already-measured values.

---

## 3. What SPI Means

**SPI = Serial Peripheral Interface**

| Word | Meaning |
|---|---|
| Serial | Data is sent one bit at a time on a single wire |
| Peripheral | Designed for connecting peripheral devices (sensors, memory, displays) |
| Interface | The set of rules and signals for the connection |

---

## 4. The Four SPI Signals

Classic SPI uses four signal lines:

### SCK — Serial Clock

```
STM32 ─────── SCK ───────► Sensor
```

- Generated by the **master** (MCU)
- Both devices use this clock to know *when* to send or sample a bit
- Without a shared clock, there is no way to know when a bit is valid

### MOSI — Master Out, Slave In

```
STM32 ─────── MOSI ──────► Sensor
```

Data travels **from master to slave**.  
"Out" from the master's perspective, "In" from the slave's perspective.

### MISO — Master In, Slave Out

```
STM32 ◄────── MISO ─────── Sensor
```

Data travels **from slave to master**.  
"In" from the master's perspective, "Out" from the slave's perspective.

### CS / SS — Chip Select / Slave Select

```
STM32 ─────── CS ────────► Sensor
```

Tells a specific slave: "You are selected. Participate in this transaction."

**CS is usually active-low:**
- CS = HIGH → slave is **not** selected (ignores MOSI, doesn't drive MISO)
- CS = LOW → slave **is** selected (processes MOSI, drives MISO)

---

## 5. Master and Slave

**Master** — controls the communication:
- Generates SCK
- Selects which slave (drives CS)
- Initiates the transfer
- Example: STM32, ESP32, FPGA

**Slave** — responds to the master:
- Waits to be selected
- Responds when CS goes low
- Uses master's SCK to synchronize
- Example: MPU-6500, flash memory, DAC

---

## 6. Why SPI is Synchronous

SPI is **synchronous** because both devices use the **same clock** (SCK) to synchronize data transfer.

Compare this to **asynchronous** UART, where both sides must agree on a baud rate in advance, and there is no shared clock — timing errors accumulate over long messages.

In SPI:
- The master generates SCK
- Both master and slave act at specific edges of SCK (rising or falling)
- There is no baud rate setting — the clock itself is the reference

This makes SPI very reliable for high-speed transfers.

---

## 7. Full Duplex

SPI has **two separate data lines**:

```
MOSI  →  Master to Slave (one direction)
MISO  →  Slave to Master (other direction)
```

Because the lines are separate, both can carry data **simultaneously**.

During the same clock cycle:
- Master sends a bit on MOSI
- Slave sends a bit on MISO

This is called **full duplex** — data flows in both directions at the same time.

---

## 8. Serial vs. Parallel

**Parallel communication** sends multiple bits at once — one wire per bit.

```
8-bit parallel: D7 D6 D5 D4 D3 D2 D1 D0
                 │   │   │   │   │   │  │  │
                ── ── ── ── ── ── ── ──   (8 wires)
```

**Serial communication** sends one bit at a time on a single wire.

```
8-bit serial on MOSI:
  Time: ─► 1  0  1  0  0  1  0  1
                (one bit per clock)
```

SPI is serial — it uses fewer wires but takes multiple clock cycles per byte.

---

## 9. Multiple Slaves on One Bus

Multiple slaves can share SCK, MOSI, and MISO.  
Each slave has its own **dedicated CS line**.

```
                    ┌── Sensor 1
SCK  ───────────────┼── Sensor 2
                    └── Sensor 3

                    ┌── Sensor 1
MOSI ───────────────┼── Sensor 2
                    └── Sensor 3

                    ┌── Sensor 1
MISO ───────────────┼── Sensor 2
                    └── Sensor 3

CS1 ─────────────────── Sensor 1
CS2 ─────────────────── Sensor 2
CS3 ─────────────────── Sensor 3
```

**For 3 slaves: 3 shared lines + 3 CS lines = 6 MCU signal connections**  
(not 4 × 3 = 12, because SCK/MOSI/MISO are shared)

---

## 10. The Hi-Z (High Impedance) Secret

**Problem:** All three sensors physically connect to the same MISO wire.  
If all three drive MISO simultaneously, their signals would collide and corrupt data.

**Solution:** SPI slave devices have a **tri-state output**.

When a slave's CS is HIGH (not selected):
- The slave's MISO pin enters a **high-impedance (Hi-Z)** state
- It does not actively drive the wire — electrically, it is as if disconnected
- The selected slave is the only one driving MISO

```
CS1=HIGH  →  Sensor 1 MISO in Hi-Z  (not driving)
CS2=LOW   →  Sensor 2 MISO active   (driving data)
CS3=HIGH  →  Sensor 3 MISO in Hi-Z  (not driving)
```

Only one CS should be LOW at any time to avoid bus contention.

---

## 11. Only One CS Should Be Active at a Time

If two CS lines go LOW simultaneously:
- Both slaves think they are selected
- Both attempt to drive MISO
- Bus contention occurs — signals corrupt each other
- Can cause excessive current and hardware damage in some designs

**Rule: Assert exactly one CS LOW at a time when slaves share MISO.**

---

## 12. SPI vs. I²C

| Feature | SPI | I²C |
|---|---|---|
| Wires | 4 (SCK, MOSI, MISO, CS) | 2 (SCL, SDA) |
| Device selection | CS pin per slave | 7-bit address |
| Duplex | Full duplex | Half duplex |
| Speed | Generally faster | Generally slower |
| Slave selection overhead | CS line management | Address byte in each transfer |
| Pins per additional slave | +1 CS | +0 (uses address) |
| Complexity | Lower protocol overhead | More protocol structure |

Neither is universally better — the choice depends on the application.

---

## 13. SPI Advantages

- High transfer speed
- Simple protocol — no addresses, no arbitration
- Full duplex — can send and receive simultaneously
- Very low overhead per bit
- Widely supported by sensors, memory, displays, ADCs, DACs

---

## 14. SPI Limitations

- Requires one CS wire per slave (more wires as slaves increase)
- No built-in acknowledgment mechanism (unlike I²C ACK)
- No error detection in the SPI standard itself
- Master must manage CS timing and sequencing
- Each device's command/register format is device-specific (not defined by SPI)

---

## 15. The Important Sensor-Transfer Distinction

A common misconception:

> "SPI reads sensors simultaneously."

More accurate:

> "SPI transfers data sequentially — but sensor sampling and SPI readout are two separate things."

```
Layer 1: Physical reality (acceleration, rotation)
              ↓
Layer 2: Sensor sampling circuitry (converts physical signal to digital)
              ↓
Layer 3: Sensor internal registers / FIFO (stores measurement)
              ↓
Layer 4: SPI interface (transfers stored data to MCU) ← SPI operates here
              ↓
Layer 5: MCU (processes and uses the data)
```

If three IMUs internally sample at the same physical instant (via a hardware SYNC pin), the STM32 can read them sequentially over SPI and still have measurements that were captured simultaneously.

**SPI transfer timing ≠ sensor sampling timing.**

This is one of the most nuanced points about SPI in embedded systems.
